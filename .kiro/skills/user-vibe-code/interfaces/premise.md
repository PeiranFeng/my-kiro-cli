# 接口：premise

验证代码所依赖数据的前提与取值边界。只读，只在回复里呈现，不写文件。

## 步骤

1. 列出代码消费的每份数据，以及调用的每个外部接口，指出它们的生产方。接口按 `principles/data-contract.md` 的"调用的接口也有契约"核实。
2. 对每份数据，按 `principles/data-contract.md` 的查证顺序取证：生产方的强制手段，生产方的声明，真实数据的只读统计，领域常识。
3. 需要真实数据时：数仓数据按 `user-snowflake` skill 只读查询；本地文件在仓库之外的目录运行（`50-project-facts.md#no-run-in-repo`）。统计只用于确认契约，命令不进业务代码。
4. 为每项契约标注强度，并给出消费方应有的落点。
5. 写回复，交出前按 `checklist.md` 的五打分。

## 契约强度

| 强度 | 含义 | 消费方的落点 |
|---|---|---|
| 强制 | 生产方用类型、schema 约束、写入前校验或健康检查保证 | 信任，注释一句话 |
| 声明 | 生产方的文档或 docstring 写明，无强制手段 | 入口处验证一次 |
| 快照 | 只由某一时刻的真实数据统计得出 | 入口处验证，并告知用户该契约会随上游变化 |
| 推断 | 只由领域常识或命名推出 | 入口处验证，并请用户确认 |

## 回复内容

每份数据一段，含：生产方、每项契约（量纲、取值范围、可空性、粒度、有序、去重）、依据位置、强度、消费方的落点。契约与实际数据不符时，列出不符之处，由用户决定修生产方还是改契约。
