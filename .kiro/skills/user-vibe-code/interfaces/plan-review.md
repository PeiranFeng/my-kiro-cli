# 接口：plan-review

评估一份开发方案是否满足本 skill 的约束。方案指 specification、设计文档、实现步骤、迁移计划等开发蓝图，来自上游或由 AI 生成。AI 编程的失误常在方案阶段已经写定，所以在写代码之前审方案。只在回复里呈现，不写文件，不改代码，不改方案。

## 触发

- 用户手动要求评估某份方案。
- develop 的方案关卡：写代码前对开发计划执行一次，结论不是"通过"时不写代码。

## 评估对象

用户给出的方案文档或对话中的方案文字，按 `objects/方案.md`。作为 develop 的方案关卡 时，对象是用户已确认的方案加上拟定的实现步骤；没有书面方案时，先把步骤写成清单再评估。读文件或执行 git 前先明确目标仓库与路径（`40-git-safety.md#identify-repo`）。

## 步骤

1. 按 `objects/方案.md` 列出方案的各项，读方案所指的代码，按其中指定的 `checklist.md` 部分逐项打分，答"否"的写成发现；豁免规则同 `interfaces/code-review.md`。
2. 给出结论，写回复，交出前按 `checklist.md` 的五打分。发现了 `principles/` 与原则库里都没有的方案类问题时，转 `interfaces/analysis.md`。

## 结论

三选一：

- 通过：没有必须处理的发现。
- 需修改：有发现须先改方案，改完重新评估。
- 需确认：存在只有用户能回答的点，只列出该项。

## 回复内容

结论在前，随后列出方案中的问题，组织方式与原则标注同 `interfaces/code-review.md` 的"回复内容"；位置写方案的章节或步骤，涉及代码时附文件与行号，处理建议为删除、改写、补充缺项或请用户确认。
