# 模块之间的结构

方案与代码中模块之间的关系：依赖、调用、构造、格式与分层。单个函数、类的职责见 `scope.md` 的"简单优先"；类与方法层面的设计原则在 steering `20-engineering.md` 的"OOP 设计"一节，原文以 steering 为准，本文件只写模块之间的部分。代码层面的细审归 `user-review`。

## 依赖朝一个方向

模块之间的依赖不形成循环。方案声明了分层时，每一处新增或移动的依赖都服从该分层：下层不依赖上层，同层的两侧不跨到对方的职责里。

## 只用直接依赖的公开接口

调用方只与直接依赖交互，只用被调方的公开接口；判断与决策交给持有数据的一方（`20-engineering.md#law-of-demeter`、`#tell-dont-ask`）。私有成员被别的模块调用，说明它属于公开接口，或调用方承担了被调方的职责。

## 构造入口唯一

同一种对象只有一个构造入口，构造所需的步骤（解析、实例化、选择形态、校验）集中在该入口内，不拆到调用方与被调方两处。谁创建谁持有，见 `20-engineering.md#ownership-lifecycle`。

## 格式只在一处定义

序列化格式、表结构、协议的写与读由同一处定义，写入方与读取方都引用它。格式分处两地，任何一处修改都要同步另一处。

## 改动处的结构

修改既有代码时，改完的结构应像一开始就这样设计的，不靠叠加补丁让改动最小；这只适用于被改动的函数和类。范围之外的重构先问用户（`00-collaboration.md#stay-on-task`）。
