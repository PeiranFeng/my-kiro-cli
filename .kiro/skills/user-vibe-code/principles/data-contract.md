# 数据契约

## 边界由生产方的承诺决定

每份数据有一个生产方。数据的取值边界等于生产方对它的用途、量纲、范围、可空性、粒度、顺序、去重所作的承诺，合称契约。消费方的责任是读懂并依赖契约；契约以外的用途、取值不在消费方的保护范围内。

某个取值落在契约外，说明生产方有缺陷或消费方误用了数据，两种情况都应暴露出来，由对应的一方修正，消费方不在自己这里补偿。

## 查证顺序

按可信度从高到低（综合：由 `20-engineering.md#guarantee-data-property` 的保障级别与用户案例展开，待验证），执行方法见 `interfaces/premise.md`：

1. 生产方的强制手段：类型、schema 约束、写入前的校验、上游的健康检查与告警、生产方自己的测试。有这一层，消费方可以信任。
2. 生产方的声明：模型描述、README、docstring 里写明的前提。只有声明、没有强制时，消费方在入口处验证一次。
3. 对真实数据做一次只读统计：最小值、最大值、分位数、空值率、唯一性、量纲。统计是某一时刻的快照，不是承诺；结论要注明时间点与范围，消费方在入口处验证。
4. 领域常识：数据代表什么物理或业务量，它的数量级和符号意味着什么。常识只能提出假设，须经前三层或用户确认。
5. 询问用户：前四层都得不出结论时，只问那一个具体的前提。

## 调用的接口也有契约

调用的库函数、框架接口和仓库内部函数，其签名、参数含义、返回值与异常，以实际安装的版本和源码为准。每个 import 和外部调用在写入前确认存在且用法正确，方法是读源码、查锁文件，或导入后检查；不凭"应该存在"下笔。依据见 `sources.md`。

## 契约的落点

查到的契约，按 `20-engineering.md#guarantee-data-property` 的三级选一级保障：

- 验证：外部输入，或前提难以保证、强度只到声明、快照、推断时，在入口处 assert 或 raise。
- 假设：强制层已保证的热路径不变量，在类型注释或文档中声明，调用方负责保证。
- 注释：提示维护者的依赖，一句话。

算法依赖数据的有序、去重、值域、稀疏程度时，按这些特性选算法，不用"通用但保守"的方案（`20-engineering.md#match-algorithm-to-data`）。

## 契约不明时

- 查不到任何声明，数据又来自自己无法控制的一方：在入口处校验，并在回复里告诉用户这份契约是假设，请其确认。
- 上游由用户掌握：直接问用户契约是什么，不用在消费方堆分支来覆盖所有可能。
- 契约与实际数据不符：报告给用户，由用户决定修生产方还是改契约。
