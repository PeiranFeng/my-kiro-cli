# AI 编程的常见失败形态

review 与写后自查时对照的形态目录。每条给出形态、检出方法与对应原则；出处与验证情况见 `sources.md` 的"约束 AI 编程的公开实践"，成因均为来源的解释，未经独立验证。实际遇到的新形态由 `interfaces/analysis.md` 记入 `domain/ai-dev-problems.md`。

## 防御类

- 吞掉异常：宽泛的 except 包住操作，出错时返回空、零或"安全值"。检出：找返回空值的 except，问调用方能否区分错误与正常的空结果。对应：`failure.md`、`defensive.md`。
- 为已排除的情形加防御：对类型或契约已保证的值再判空、查类型、查真值；hasattr、getattr、isinstance 的探测链；对刚构造的值再判空；无基准、无声明、无回退用例的 try-import 回退。检出：对每个判断问"在真实调用下它能否为真"。对应：`defensive.md` 的三问，信任边界处不适用。

## 熵类

- 单实现的抽象与推测性配置：只有一个实现的接口、工厂、注册表；没有调用方的开关与可选参数；只在一处读取的全局开关；只转发同样参数的包装函数。检出：数现存的使用方与调用点。对应：`repo-conventions.md` 的抽象准入与"不为未来预留"。
- 重写已有函数或并存克隆：与已有函数等价的新函数，`_v2`、`_new`、`_impl` 与原函数并存，重复粘贴同一段逻辑。检出：对新函数在仓库里搜索相近实现，空结果换一种方法二次确认。对应：`repo-conventions.md` 的"先找现成的再写"。
- 清理时悄悄改变行为：去重、简化时顺手改了公开的错误类型、时序或语义。检出：对比改动前后的异常类型、返回值与副作用。对应：`repo-conventions.md` 的"清理与重构保持行为不变"。
- 偏离周边写法：命名风格、错误处理、日志、HTTP 或数据库工具与周边不一致。检出：读同文件和一个相邻文件后对照。对应：`repo-conventions.md` 的"入乡随俗"。

## 契约类

- 调用不存在的接口或包：import、方法名或签名在实际安装的版本里不存在。检出：逐个核对 import 与调用的签名，读源码或查锁文件。对应：`data-contract.md` 的"调用的接口也有契约"。
- 占位成功：返回硬编码的成功值、夹具数据或 TODO 占位。检出：找硬编码返回值与 TODO。对应：`failure.md` 的"未实现时显式失败"。

## 测试类

- 迁就测试：为让测试通过而改期望值、放宽断言、跳过用例，或在实现里为测试输入特判。检出：比较测试在改动前后的期望值。对应：`testing.md` 的"不迁就测试"。
- 无效测试：只断言 mock，字面量断言，同一场景换名重复，测错了对象。检出：问"这个用例会因真实原因失败吗"。对应：`testing.md` 的"避免无效的测试"。
- 期望值与实现同源：期望值走与被测实现相同的代码。检出：追踪期望值的计算路径。对应：`testing.md` 的"期望值有独立来源"。
