# 对象：方案

specification、设计文档、实现步骤、迁移计划等开发蓝图，来自上游或由 AI 生成。AI 编程的失误常在方案阶段已经写定，方案的好坏主要体现在元素之间的关系上，所以先把关系列出来，再逐项检查。

## 列出

从方案原文列出下列各项，方案没写的写"未写"：

1. 需求项。
2. 计划新增、修改、删除、移动的每个对象：函数、类、模块、参数、配置项、文件、表。
3. 模块之间的关系：每一处跨模块调用（调用方、被调方、调用的成员是否公开）、每条新增或移动的依赖，以及方案声明的分层。
4. 构造与持有：每种新增或改动的对象由哪里构造、由谁持有。
5. 数据流与格式：每份数据在哪里产生、经过哪些环节、在哪里被读；每份格式的写入方与读取方。
6. 消费的数据与调用的外部接口，各自的生产方。
7. 行为变化。
8. 计划写的测试，以及期望值的来源。

## 读代码

读方案所指的代码：被改动处的上下游、同类实现、方案声称"已有"或"不存在"的对象。模块依赖以源码中的 import 为准。读取范围限于方案涉及的文件与必要的类型实现。

## 打分

对上面列出的每一项，按 `checklist.md` 的一、二逐项打分；方案含测试计划时加四。
