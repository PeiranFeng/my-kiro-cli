# user-auto-score

由用户显式调用 `/user-auto-score` 开启，开启后每一轮都执行，直到用户主动说退出才停止。用户未开启时不执行。

一轮 = 从一次用户 prompt 到一次 agent 回复之间的全部工作。生效期间的每一轮，都在输出回复之前完成"自评—修正"闭环，回复只呈现任务结果与修正历史。

## 指令优先级

用户当轮 prompt 是最高优先级指令，与 steering 冲突时以 prompt 为准（`00-collaboration.md#user-word-is-final`「用户的话大过天」已确立此序，本 skill 补充它在评分中的用法）。

prompt 未提及的方面，steering 条目与 prompt 同级——它们是用户的默认决断，不因未被提及而降级。

prompt 语义不明时，动手前先指出不明处并请求澄清；只有语义明确的部分才能作为已知条件进入执行。此时本轮的输出就是澄清请求，评分只针对"提出澄清"这一行为。

## 评分清单

steering 文件全文常驻上下文，逐文件逐条枚举其语义标题即得清单，覆盖全部条目而不限于带 `[review]` 标记的项。

逐项对本轮行为打 1-5 分，并遵守：

- 每个分数附一条依据，指向本轮的具体行为或工具输出。
- 本轮行为未涉及的项标为不适用，不参与阈值判定。
- 某项被 prompt 中优先级更高的指令覆盖时，标为 steering 失效并记录覆盖它的那句 prompt，不参与阈值判定。

枚举、打分、判定与修正全程依靠自身推理完成，不写脚本、不跑命令来代替这一过程。

## 修正循环

1. 本轮工作完成后先自评全部条目。
2. 任一参与判定的项 ≤2 分时进入修正轮：按该条目的要求修复行为与产出，或判定该条在本轮失效并记录依据。
3. 修正后重新对全部条目评分。
4. 重复至所有参与判定的项都 >2 分，才向用户输出回复。

## 回复内容

回复正文只包含本轮任务结果与修正历史，其中只有修正历史可以提及 steering 条目；评分表、分数与条目原文留在过程中。

修正历史用有序列表分行列出，每行一句话概括一次修正。
