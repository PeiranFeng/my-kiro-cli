# bootstrap review

`review bootstrap` 审查 `bootstrap` 产出的 draft 文档是否忠实于现状，只回答"是否忠实"，不评价设计好坏；好坏由普通 `review` 按 `principles/` 判断。

## 忠实性原则

### 架构忠实于代码

文档中每条陈述都能在代码里找到依据；代码里的显著行为都在文档中有对应陈述。显著行为的类别：能力探测（对属性、方法、覆盖关系的字符串探针）、分支选择（按类型、配置或参数选择实现）、对外可见的副作用、错误条件、阈值与哨兵常量。现状违反设计原则之处照实记录，不改写成理想设计；无法从代码得知的内容省略，不推测。

### 需求忠实于架构

每条需求都能追溯到架构文档中的某条陈述，只抽象其中调用方可观察的行为；架构文档中调用方可观察的行为都有对应需求。需求不补充架构里没有的行为，不把现状改写成更理想的行为；架构里有缺陷或不合理之处，需求照实写出，由用户审查需求时判断。

## 方法

1. 代码 → 架构：运行 `scripts/list_probes.py --project-root <目标仓库>` 列出字符串探针，并结合结构文档的「动态探测」；再按显著行为的类别逐模块枚举代码里的行为，逐项在架构文档中找对应陈述。
2. 架构 → 代码：每份被抽读的架构文档，其中每条陈述都要在代码里找到依据，附 `grep` 或阅读的位置。
3. 架构 → 需求与需求 → 架构：两个方向都检查，只检查一个方向不算完成。
4. 核对 `bootstrap-report.md` 中的事实断言，每条附证据；核对只是辅助，不能代替前三步。
5. 影响语义的未决问题已写入对应文档的 `## 待确认`，而不只写在 `bootstrap-report.md` 里。

## 输出

报告写入 `.project-spec/reviews/<yyyy-mm-dd>-bootstrap.md`，发现的格式同 `review.md`，另含「覆盖范围」一节：已读文档数与总数、已检查的方向、没有检查的方向。

## 修改

`bootstrap` 命令在 review 之后按发现修改一轮，然后重新校验：

- 文档与现状不符的发现，修改文档使其忠实于现状。
- 现状违反设计原则的发现，不改文档也不改代码，记入 `bootstrap-report.md`。
- 仍无法解决的问题记入 `bootstrap-report.md`。
