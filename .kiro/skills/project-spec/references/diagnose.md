# diagnose

`diagnose [模块]` 基于文档快速整理当前项目悬而未决的问题，分点列出，每一条都是创建 issue 的候选点。只读：不写文件，不读代码，不创建 issue。

## 来源

运行 `scripts/collect_issues.py --project-root <目标仓库>`，它列出四类原始条目：

- 文档中「待确认」小节的条目。
- `.kiro/project-spec/<仓库目录名>/bootstrap-report.md` 与 `maintain-report.md` 的条目（不含「无法验证」一节）。
- 校验报告里的错误、文档与代码不一致、没有架构文档的源文件。
- 用例文档中标注「无现有测试」的数量。

报告可能落后于文档，两者冲突时以文档为准。目标仓库没有 `docs/` 时，提示先运行 `bootstrap`。用户给出模块时，只保留与该模块相关的条目。

## 整理

1. 同一问题出现在多个来源时合并成一条，并列出全部来源。
2. 剔除不是问题的条目：仅作说明的记录、已经解决的修订记录。
3. 归入四类：
   - 未决语义：需要用户决定。
   - 现状缺陷：现状不合理、违反设计原则或没有解决方案。
   - 文档漂移：文档与代码或文档之间不一致。
   - 覆盖缺口：缺少文档、缺少测试或未核对。
4. 每条写成「名词短语：一句话说明（来源路径）」，不超过两句，不评定严重度，不提出解决方案。仅凭文档无法判断是否仍成立的，标注「需读代码确认」。

## 输出

按类别分点列出，末尾给出总数和各类数量。创建 issue 是对远程的操作，用户另行要求并确认内容后才执行。
