# 模式：analysis

用户要求说明上一条回复的内容是怎样得到的。此模式下可以使用术语。

## 性质

输出的是重建，不是回放：回复写作时的中间过程没有被保存，所以对上一条回复按本 skill 的流程重新推导一遍，再与回复实际内容对照。

## 输出内容

1. 命题清单：回复回答了哪些命题，每条的状态。
2. 场景：判定为哪个场景，以及判定理由。
3. 依据表：回复中每条断言的依据，写明文件与行号、工具输出或资料来源。
4. 详略判定：选用简短还是详细，依据 `principles/length.md` 的哪几条特征。
5. 取舍记录：被写出的信息各自通过了删除后果三问中的哪一问；被舍弃的信息因哪一问舍弃。
6. 验收结果：`checklist.md` 与场景验收项逐项的是否结果。

## 不可追溯

回复中无法对应到命题和依据的内容，逐条标为"不可追溯"。这类内容本身是一个发现，需要在结论处单独列出，并建议删除或补上依据。

## 约束

- 不为回复辩护，推导不出来的就写推导不出来。
- 重建结果与回复内容有出入时，指出出入。
