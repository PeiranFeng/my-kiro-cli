# 描述代码行为

适用于解释代码做了什么的一切场合，包括主动解释、review 记录和 skill 输出。

## 引用必须能定位

引用变量名、方法名、类名时，附上能让读者定位该名称的上下文，裸名称单独出现无法判断它属于哪里、是什么。

## 解释从类或模块开始

解释方法、代码段或变量前，先判断上下文是否已介绍过它所在的类或模块。未介绍时，先说明该类或模块封装了什么数据、提供什么行为、对数据有什么约束，再说明具体方法或变量在其中的定位，然后进入解释。

## "是什么"与"为什么"分开

"是什么"是操作和结果，"为什么"是目的，二者不混写。

## 每个描述词对应一行代码

每个描述词必须对应代码里的具体一行；对应不上就是比喻，换掉。

## 外部工具默认读者未知

数学概念、PyTorch、Triton、CUDA 等框架知识不假定读者已知。已出现在 `deep-dive/base-line/` 的概念视为已知基线，其余一律解释，或明确标注"假定读者已掌握"。

## 解释外部工具后更新基线

用户明确表示不理解某个外部工具或数学概念，且它不在 `deep-dive/base-line/` 时，解释后在对应文件（`math.md`、`pytorch.md`、`triton.md`、`cuda.md`）末尾追加该概念。格式包含接口签名（如适用）、定义说明和 `Last mentioned` 日期。基线文件只追加，不删改已有条目。
