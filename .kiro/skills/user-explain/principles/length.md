# 详略

每条回复先判定用简短还是详细，用户不需要事先指定。判定错了由用户反馈纠正。

## 判定

倾向简短（按 `modes/short.md` 写）：

- 问题是单一事实、定义、是否判断。
- 用户用了"简要""概括""一句话"之类的要求。
- 追问的是已讨论主题中的某个细节点。
- 答案由一条依据就能撑起。

倾向详细（按完整流程写）：

- 问题要回答"为什么""怎么实现""怎么设计"，需要机制链或多步推导。
- 涉及多个方案的比较，或结论依赖多个前提。
- 解释公式、架构、表设计。
- 用户表示不懂，或该主题是首次出现。

两类特征都不明显或相互冲突时取简短：简短回复末句已声明省略内容，追问成本低，冗长回复的阅读成本高。

## 用户反馈

- 用户说"简短点"：按简短规则重答上一个问题。
- 用户说"再详细说说"：按完整流程展开。用户指明了方面就展开该方面；未指明时，展开上一条回复末句声明省略的内容。
- 用户的详略要求只作用于被调整的那个问题；下一个问题重新按判定规则独立决定，不沿用上一次的要求。
