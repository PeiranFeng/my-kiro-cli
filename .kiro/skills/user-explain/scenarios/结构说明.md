# 场景：结构说明

## 判断

解释架构、模块关系、目录组织、数据表设计。

## 方法

- 先整体后部分：先说整体负责什么，再逐个说明组成部分。
- 说明每个类或模块时，先说它封装的数据、提供的行为和对数据的约束，再说细节。
- 写明部分之间的依赖方向与数据流向，以及这样划分的理由。
- 表设计：说明一行代表什么，主键与粒度，字段是否各自只表达一份独立信息，以及上下游的查询路径。
- 评价设计好坏时，依据是读者的使用目标，列出满足与不满足之处。

## 必答要素

- 整体职责。
- 组成部分及各自职责。
- 部分之间的依赖方向与数据流向。
- 划分的理由。
- 表类追加：粒度、键、字段含义、与上下游表的关系。

## 验收

- 第一句说整体。
- 每个部分先说职责再说细节。
- 依赖方向明确。
- 没有裸名词，每个名称都有可定位的上下文。
