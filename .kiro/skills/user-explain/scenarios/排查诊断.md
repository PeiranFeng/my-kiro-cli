# 场景：排查诊断

## 判断

在若干可能的原因中定位真实原因：性能调查、故障定位、结果异常。

## 方法

- 先列已观察到的事实，再列候选原因。
- 对每个候选做必要条件检验，目标现象出现时候选缺席的，予以排除。
- 余下的候选用七项解释标准比较，选出当前最佳解释。
- 把"观察到的"与"推断的"分开写，不混为一谈。
- 提出下一步检验时，要求它能区分至少两个候选，并写明各候选下预期看到什么。

## 必答要素

- 已观察事实。
- 候选原因，以及每个候选被排除或保留的依据。
- 当前最佳解释，以及它尚未解释的事实。
- 下一个能区分候选的检验，及各候选下的预期结果。

## 验收

- 每个排除都有观察依据。
- 结论标明是观察还是推断。
- 下一步检验能区分候选，且结果可证伪该候选。
- 简单解释可行时没有引入新的实体或机制。
- `static` 模式下，下一步检验只提出，不执行。
